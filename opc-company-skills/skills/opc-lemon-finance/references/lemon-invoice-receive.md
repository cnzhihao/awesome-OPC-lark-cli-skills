# 收票与一键取票

## 适用范围

处理进项发票查看、税局取票准备、电子发票文件获取状态和暂不入账清单。收票不等于认证或入账。

## 页面路径

`发票 → 进项发票` 查看已有记录；`发票 → 一键取票` 准备从税局获取数据；进项页面的“暂不入账发票”用于查看隔离记录。

## 只读流程

1. 先做 `lemon-context` 检查。
2. 读取进项发票、商品明细和暂不入账发票三个视图；记录期间、票种、状态和已有记录数。
3. 对用户给出的发票号、供应商、日期或金额进行页面内检索；找不到时报告查询条件，不直接新增。
4. 检查是否已经存在相同的发票代码/号码（或数电发票号码）、开票日期和价税合计。
5. 输出“已存在、疑似重复、未找到、待人工核验”四类结果。

## 一键取票准备

一键取票页面可能同时获取进销项发票数据和电子文件，并要求设置开始/结束日期、验证税局登录状态。日期范围上限和必填条件以当前页面提示为准；不要把上一次任务的日期带入本次任务。

在点击“下一步”或“立即获取”前，先展示：

```text
取票公司/账套：<名称>
日期范围：<开始至结束>
目标数据：<进项/销项/电子文件>
已有匹配：<数量>
预期写入：<柠檬云发票模块>
```

只有用户明确确认“获取这段范围的发票”后，才可以执行一次取票。若页面要求税局密码、验证码或其他认证，停止交给用户，不读取或保存凭据。

## 状态处理

建议使用业务状态：

`候选 → 已取票 → 待查验 → 待认证 → 暂不入账/待入账 → 已入账`

- “已取票”只表示数据已进入发票模块，不表示真实性或抵扣资格已经确认。
- “待认证”“入账”属于后续高风险动作，不能在取票后自动继续。
- 发现税率、购买方、价税合计、附件或供应商信息不一致，标记为待复核。

## 输出

```text
取票范围：<日期/票种>
已有记录：<数量>
新增候选：<数量；尚未点击获取时写“未执行”>
疑似重复：<数量>
待复核：<数量及原因>
下一步：<是否需要用户确认取票/认证/入账>
```

## 禁止

不得自动批量认证、入账、生成凭证、导出文件、删除发票、红冲或作废；不得把取票确认扩展为认证或入账确认。
